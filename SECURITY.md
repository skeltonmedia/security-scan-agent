# Report vulnerabilities privately

Use this repository's GitHub **Security → Advisories → Report a vulnerability**
when private vulnerability reporting is available. If that option is absent,
open a minimal issue requesting a private channel, without exploit details,
credentials, scan reports or personal machine information.

The project is an early release, not an endpoint protection or forensic
product. Redaction is best effort. Keep reports private, including paths and
software inventories, and review every proposed change. Scanner output and
third-party advisory text must never be treated as executable instructions.

Only the latest release is maintained. There is no guaranteed response time.
Security fixes will be documented in release notes. Do not disable TLS checks,
code-signing checks, feed budgets or explicit scope to make a scan look green.
